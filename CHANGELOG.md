# Changelog

Notable changes to this project. Releases follow `MAJOR.MINOR`: `VERSION` states the current release, each
release directory carries its own `VERSION`, and frozen archives under `releases/<version>/` are never
rewritten or renamed.

## [Unreleased] - repository layout normalisation (no result changes)

### Changed

- One naming scheme for every versioned area: `data/` -> `data/v1.0/`, `data_v2/` -> `data/v2.0/`,
  `data_v21/` -> `data/v2.1/`, `data/results/` -> `results/v1.0/`, `results_v2/` -> `results/v2.0/`,
  `results_v21/` -> `results/v2.1/`, `configs/v2/` -> `configs/v2.0/`, `configs/v21/` -> `configs/v2.1/`.
- Version 1.0 deliverables moved out of the project root: `report.pdf` -> `report/v1.0/report.pdf`,
  `site/` -> `site/v1.0/`.
- `backup/` -> `archive/`, with snapshots renamed `<YYYY-MM-DD>-<slug>/` and an index in `archive/README.md`.
- `src/paths.py` is the single source of truth for versioned roots; `src.paths.resolve()` still maps the
  pre-migration names recorded inside frozen artifacts.
- `.github/workflows/v2-cpu-contracts.yml` -> `.github/workflows/release-contracts.yml`. It always ran both
  the Version 2.0 and Version 2.1 contracts, so the name now matches the content.

### Added

- `VERSION` is now read as the current release. Each packager compares versions numerically instead of
  requiring an exact string, so `tools/package_v2.py` no longer fails on a 2.1 tree.
- `releases/2.0/VERSION` and `releases/2.1/VERSION` so every release directory states its own version.
- `docs/MIGRATION-2026-09-23.md`: the rename map, the tracked/ignored policy and the audit evidence.
- `results/v2.1/provenance.json` gained a `layout_migration` annex. The certified pre-training hashes in
  `code` are unchanged; the annex records the audited pre- and post-migration hash of every file this change
  touched. `checks.v21_verify` validates the annex and accepts only the certified or annexed hash.
- Version 1.0 evidence metadata is now under version control: `data/v1.0/provenance/` (including the 20
  Animals-10 probe images that `pipelines.supplement` depends on) and the JSON records under `results/v1.0/`.

### Fixed

- `.gitignore` no longer drops tracked evidence. The first draft of the rewritten rules ignored
  `data/v2.1/manifests/lock.json` and `data/v2.1/manifests/long_tail/`, which were tracked before the
  migration; all six files are tracked again. Every path that was tracked at the previous commit was
  checked against the new rules and none is ignored now.
- `.gitignore` keeps the generic hygiene rules that the rewrite had dropped: Python caches and virtual
  environments, `.env` files, editor and OS files, and the `*.zip` / `*.faiss` / `*.tar.gz` style safety
  net, with the frozen release archives still un-ignored on purpose.

### Removed

- Duplicate root copies of `Assignment1-submission.zip`, `Assignment1-submission.zip.sha256` and
  `MANIFEST-1.0.json`. The authoritative copies remain in `releases/1.0/`; the deleted copies were verified
  byte-identical first.

### Notes

- No experiment, metric, figure, lock or frozen release archive was modified. `releases/1.0/`,
  `releases/2.0/` and `releases/2.1/` keep their original names by design.
- `results/v2.1/verification.json` predates this change and is regenerated by `python -m checks.v21_verify`
  on the GPU host.
- Documents under `docs/session/`, `docs/report/V2-EXECUTION-LOG.md`, `docs/report/V2-RESULTS.md`,
  `docs/report/V21-RESULTS.md`, `docs/report/REPORT-REVISION.md` and `docs/releases/RELEASE-1.0.md` are
  historical records and intentionally keep the paths that were current when they were written.

## [2.1] - 2026-09-23

Audit-driven revision of Version 2.0. Removes conflicting/duplicate image content, fixes group macro-F1 and
exact-search tie handling, saves selected models and predictions, and uses allowlisted public packaging.
Known-class train/validation/test budgets became 20/8/8; the 10:1 long-tail setting uses 20:2 over five
seeds. 2.1 certifies feature-conditional reproducibility only: it hash-verifies frozen Version 2.0 features
by image ID and does not re-encode images. SOP/SIFT measurements remain historical Version 2.0 evidence.
See `docs/report/V21-RESULTS.md` and `releases/2.1/RELEASE-2.1.md`.

## [2.0]

Adds independently locked SOP semantic retrieval, native-Windows SIFT1M ANN systems benchmarking, controlled
iNaturalist Birds long-tail training, calibrated near-OOD evaluation, drift monitoring, CPU CI contracts and
a health/status service. See `docs/report/V2-RESULTS.md`, `docs/report/V2-EXECUTION-LOG.md` and
`releases/2.0/RELEASE-2.0.md`.

## [1.0] - 2026-09-21

Frozen assignment submission: frozen-encoder retrieval across ResNet-18/DINOv2/CLIP, ten seeded nested
reference draws, paired bootstrap tests, a static explorer with pairwise Grad-CAM, and an 11-page report.
Archived as `releases/1.0/Assignment1-submission.zip`. See `docs/releases/RELEASE-1.0.md`.
