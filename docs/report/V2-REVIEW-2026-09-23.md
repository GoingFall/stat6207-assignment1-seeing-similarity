# Version 2.0 experimental audit — 2026-09-23

## Verdict

**Qualified acceptance of the measured headline results; corrections required for strict split independence, group macro-F1 and reproducibility claims.** Existing CI and artifact verification pass, but do not cover the issues below. No experiment inputs, frozen releases, original metrics or models were changed by this review. This is not a rerun of all model training or ANN performance benchmarks.

Reviewed baseline: Git commit `2fa9424a2b1ccda356028f2d3caa6d99d5814a89`.

## Findings, ordered by impact

### 1. High — identical image bytes cross iNaturalist development/evaluation boundaries

`pipelines/v2_prepare_inat.py:97-109` splits by IDs and classes without grouping duplicate content. `checks/v2_verify.py:78-99` verifies class/ID uniqueness but not cross-split SHA-256 uniqueness. Full rehashing found four duplicate-content groups:

- Train image 1146358 and validation image 1175657, class 1171.
- Train image 1271016 and validation image 1272159, class 475.
- Unknown-development image 496450 (class 1133) and unknown-test image 496451 (class 1114).
- Known-validation image 1897331 (class 110) and unknown-test image 1897332 (class 134).

All eight files were checked against their hashes; these are byte-identical images, not speculative near duplicates. The last two pairs also carry conflicting class labels. There are no cross-split duplicate-byte groups involving known-test in this audit. Counts are small, but strict development/evaluation independence is false; impact on selection cannot be inferred from counts alone.

**Correction:** retain 2.0 as historical evidence; define a new versioned content-group-aware split, resolve/quarantine conflicting labels, and rerun affected selection/calibration/evaluation. Include SHA-256 split-disjointness contracts. Do not edit the already frozen 2.0 manifests in place. This audit does not detect resized/re-encoded or visually near-identical images.

### 2. High — head/medium/tail macro-F1 omits cross-group false positives

`src/training/metrics.py:68-75` filters both truth and predictions to samples whose true class belongs to a group before calculating its F1. This discards predictions into that group from outside it, inflating precision and group F1. Compute per-class F1 on the entire test set, then average over the group's class IDs.

Recomputed balanced-probe examples (saved → corrected):

- Head: 0.593810 → 0.566172.
- Medium: 0.616610 → 0.585476.
- Tail: 0.591946 → 0.553988.

Overall accuracy, overall macro-F1 and reported group recall are not affected by this particular bug. Balanced data groups here are arbitrary count-tie/class-ID tertiles, not genuine imbalance groups. The same buggy function generated all long-tail group F1 values. Their numerical corrections require regenerated predictions: `pipelines/v2_train_inat.py:206-219` does not save the 15 long-tail checkpoints or per-example predictions.

### 3. Medium — exact-search boundary ties are not resolved by vector ID

`src/benchmarking/ann.py:37-48` uses distance-only `argpartition` to discard candidates before lexicographic sorting. Sorting the surviving candidates cannot recover lower-ID tied candidates already discarded.

Reproducer: 20 zero vectors, one zero query, k=5. Database shard size 3 returns `[0,1,2,3,5]`; sizes 7 and 20 return `[0,1,2,3,4]`. All are distance-exact, but the documented globally deterministic `(distance, ID)` boundary rule is not implemented.

The 256-query SIFT exact audit still passes: sharded and Flat top-1/top-10 set agreement is 1.0. This defect does not demonstrate an error in the published SIFT headline ANN recall, which uses official ground truth. Fix tie selection before discarding candidates and add a shard-invariance boundary-tie contract.

### 4. Medium — the release ZIP contains an excluded conversation transcript

The audited ZIP contains `docs/session/session-transcript.md` (58,153 bytes). `tools/package_v2.py:46` recursively includes all documentation Markdown files; `.gitignore` does not control ZIP contents. Therefore the previous statement that no transcript was uploaded is incorrect: the transcript is indirectly present in the tracked ZIP.

No dataset images, embeddings, checkpoints, indexes or per-query arrays were found in the ZIP. A limited transcript marker scan found none of `local_path`, `source_file_name`, `bird_train/`, `train_mini/`, `token`, or `api_key`; this is not a general secret-scan guarantee. Add explicit session exclusions/allowlists and issue a new audited release, preserving the historical archive and its hash.

### 5. Medium — the verification gate does not establish full experiment reproducibility

`checks/v2_verify.py:66-73,122-134,161-197` partly checks status flags, counts and hashes rather than recalculating metrics or validating every provenance link. It passes despite findings 1–3. All long-tail mean/sample-standard-deviation summaries recompute exactly, but that checks arithmetic over saved run metrics, not prediction-level correctness.

The full `config_sha256` in SOP encoding, SOP retrieval and SIFT1M results differs from the current configuration. SOP encoding's embedded SOP subsection and SIFT1M's embedded ANN/exact/SIFT subsections still match current configuration. The saved SOP retrieval JSON has no embedded subsection snapshots even though the current producer code would write them. This indicates result/code/config version drift, not proof of test-driven tuning. Current hashes cannot prove the historical ordering of preregistration and inference; the repository's first commit was made after experiments.

The DINOv2 loaders (`pipelines/v2_encode_sop.py:48-49`, `pipelines/v2_encode_inat.py:53-54`) use an unpinned model name without recording an immutable model/processor revision or weight digest. Add stage-specific immutable config snapshots, code/model/environment identifiers, explicit artifact lineage checks and retained selected checkpoints/predictions for future releases.

### 6. Medium — monitoring thresholds are demonstrations, not calibrated 1% false-alarm guarantees

`pipelines/v2_monitor_inat.py:38-55` estimates the 0.99 quantile from only 10 repeated partitions of the same validation set. Centroid and PSI null comparisons use 5,000 vs 5,000 images; evaluation uses 10,000 vs 10,000/12,150, changing their null distributions. RBF-MMD consistently subsamples 2,000 per side, so that specific sample-size objection does not apply to MMD.

All stored thresholds and monitoring values reproduce exactly, including no known-test alerts and three unknown-test alerts. These support this fixed batch comparison, not a verified deployment false-alarm rate. Use matched-size windows and a substantially larger calibration/holdout-window study before claiming a calibrated alert rate.

## Additional measurement/protocol caveats

- Batch `per_query_p95_ms` is the percentile of batch duration divided by batch size (`src/benchmarking/ann.py:85-97`), not end-to-end per-request p95. Keep the “normalized batch” label. Single-query measurements are separately available. `warmup_queries=100` is not honored by the helper, which warms one batch; single-query measurements use one repetition despite the general three-repetition setting.
- The plan asks for a validation-selected regularization grid; implementation selects learning rate with fixed weight decay. Learning curves are saved, but the planned train-vs-test overfitting gap is not reported. Treat these as explicit protocol deviations rather than completed requirements.
- No fresh all-candidate ANN timing sweep, image encoding or five-seed training was performed in this review. Reported QPS and long-tail prediction-level accuracy remain historical measurements. Far-OOD and optional WSL GPU results remain absent as documented.
